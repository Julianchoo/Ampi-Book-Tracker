# Task 01: Schema + migration

## Status

complete

## Wave

1

## Description

Adds the storage for two new features: Open Library community ratings cached on each book row, and user-defined collections (a book can be in many). Ratings are cached because Open Library is too slow to call during render; collections are a plain many-to-many.

## Dependencies

**Depends on:** None (Wave 1)
**Blocks:** task-04-queries-ratings.md, task-05-collection-actions.md, task-06-shelf-components.md

**Context from dependencies:** None.

## Files to Modify

- `src/lib/schema.ts` — new columns on `book`, new `collection` and `bookCollection` tables

## Technical Details

Project: Next.js 16 + Drizzle 0.44 + drizzle-kit 0.31 + Postgres. Config in `drizzle.config.ts` (uses `POSTGRES_URL` from `.env`). Rules from AGENTS.md: non-BetterAuth IDs are UUID `defaultRandom()`; ALWAYS `pnpm db:generate` then `pnpm db:migrate`; NEVER run drizzle push (`pnpm db:push`, `db:dev`, `db:reset`).

### Implementation Steps

1. In `src/lib/schema.ts`, add to the `book` table (after `description`/`source`, in the "snapshot" part is fine — group them with a comment):
   ```ts
   // Open Library community rating, cached: the service is too slow to ask
   // during render. checkedAt null = never looked up.
   olRating: real("ol_rating"), // 1-5 average, null when no ratings
   olRatingCount: integer("ol_rating_count"),
   olRatingCheckedAt: timestamp("ol_rating_checked_at"),
   ```
2. Add imports `primaryKey` from `drizzle-orm/pg-core` and `sql` from `drizzle-orm`.
3. Add tables after `book`:
   ```ts
   /** A user's own grouping of books ("Favourites", "Book club"). Many per book. */
   export const collection = pgTable(
     "collection",
     {
       id: uuid("id").primaryKey().defaultRandom(),
       userId: text("user_id")
         .notNull()
         .references(() => user.id, { onDelete: "cascade" }),
       name: text("name").notNull(),
       createdAt: timestamp("created_at").defaultNow().notNull(),
     },
     (table) => [
       // Case-insensitive: "Favourites" and "favourites" are one collection
       uniqueIndex("collection_user_name_idx").on(table.userId, sql`lower(${table.name})`),
     ]
   );

   export const bookCollection = pgTable(
     "book_collection",
     {
       bookId: uuid("book_id")
         .notNull()
         .references(() => book.id, { onDelete: "cascade" }),
       collectionId: uuid("collection_id")
         .notNull()
         .references(() => collection.id, { onDelete: "cascade" }),
     },
     (table) => [
       primaryKey({ columns: [table.bookId, table.collectionId] }),
       index("book_collection_collection_idx").on(table.collectionId),
     ]
   );
   ```
   (A reviewer verified offline that drizzle-kit generates `CREATE UNIQUE INDEX ... ("user_id",lower("name"))` and `PRIMARY KEY("book_id","collection_id")` from exactly this.)
4. Run `pnpm db:generate`. Inspect the generated SQL: it must only ADD columns / CREATE tables & indexes — no drops or renames.
5. Run `pnpm db:migrate`.
6. Run `pnpm typecheck` (errors unrelated to schema from other in-flight Wave 1 tasks can be ignored; schema.ts itself must be clean) and `pnpm lint`.

## Acceptance Criteria

- [ ] `book` has nullable `ol_rating real`, `ol_rating_count integer`, `ol_rating_checked_at timestamp`.
- [ ] `collection` table with uuid id, cascade FK to user, unique index on (user_id, lower(name)).
- [ ] `book_collection` with composite PK and cascade FKs to book and collection.
- [ ] Migration generated with drizzle-kit and applied with `pnpm db:migrate`; generated SQL is purely additive.
- [ ] Re-running `pnpm db:generate` reports no changes.

## Notes

Existing books get `ol_rating_checked_at = NULL`, which later tasks treat as "never looked up" and backfill lazily.
